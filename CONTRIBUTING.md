# Contributing to CAPTURR

Last updated: August 3rd, 2026

Thank you for your interest in CAPTURR. CAPTURR is a free app maintained by a single developer. This public repository makes the source code available for inspection and provides a place to report problems and suggest improvements.

## Bugs

Bug reports are welcome. Before opening an issue, please search the existing issues to see whether the problem has already been reported.

Use the bug report template and include, where possible:

- The CAPTURR version or build.
- The device and operating system version.
- Clear steps to reproduce the problem.
- What you expected to happen and what happened instead.
- Relevant screenshots or logs with all private information removed.

Please keep each report focused on a single problem.

Never include Roam Research API tokens, graph names or content, personal information, credentials, or other private data in an issue, screenshot, or log.

## Feature requests

Feature requests are welcome through the feature request template. Please describe the problem or use case as well as the proposed feature. This makes it easier to consider whether another solution may address the same need.

Suggestions will be considered, but there is no guarantee that a requested feature will be implemented or receive a response.

## Security vulnerabilities

Do not report suspected security vulnerabilities in a public issue. Follow the private reporting process in [SECURITY.md](SECURITY.md).

## Code contributions

CAPTURR is not accepting external code contributions or pull requests at this time. Pull requests may be closed without review.

You may still inspect, fork, modify, and redistribute the source code under the terms of the [GNU General Public License v3.0](LICENSE). This contribution policy only describes what is accepted into the official CAPTURR repository; it does not change the rights granted by the licence.

## Testing policy

Major new functionality must include automated tests for its testable behaviour. When functionality depends on hardware or system interfaces that cannot reasonably be automated—such as the camera, microphone, Apple Watch, or share sheet—automated tests should cover the separable logic, and the remaining manual validation must be recorded.

Bug fixes should include a regression test where practical. All existing automated tests must pass before a release.

## Support and responses

GitHub Issues are the public channel for CAPTURR bug reports and feature requests, but they are not a guaranteed support service. Response and resolution times will vary, and issues may be closed when they cannot be reproduced, are outside the scope of CAPTURR, or are not planned.

Please keep discussions respectful, constructive, and relevant to CAPTURR.
